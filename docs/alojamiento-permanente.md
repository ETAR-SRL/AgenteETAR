# Alojamiento permanente y recuperación

La PC actual debe permanecer encendida para revisiones, resúmenes y notificaciones. Cerrar el navegador no detiene esos procesos. El servicio inicia HTTP en loopback antes de conectar las fuentes y publica disponibilidad independiente; ninguna reconexión ejecuta propuestas acumuladas. Se mantienen la tarea/supervisor Windows, TLS LAN y subredes/orígenes privados explícitos existentes. No se cambió la red ni se contrató alojamiento.

Para moverlo a un equipo Windows permanente, preparar el runtime Node 24 admitido, clonar `main`, instalar dependencias con `npm ci` y seguir [inicio automático](inicio-automatico.md) y [red local](red-local.md). Configurar la ruta de instalación en el instalador, cuenta del servicio y permisos de directorios. Asegurar acceso de sólo lectura para consultas a SQL/PostgreSQL y el circuito de escritura independiente ya autorizado. No exponer las bases de datos a Internet. Ejecutar primero la batería de integración consultiva con una filial explícita.

Respaldar `.env`, `config/` local, certificado TLS y clave privada, y el directorio `DATA_DIR` completo, incluida `agent.sqlite`, configuración IA y clave documental. Guardar secretos en una copia separada y con acceso restringido; los tokens cifrados no se recuperan sin `DOCUMENTS_TOKEN_KEY`. Si cambia la dirección HTTPS, actualizar orígenes, certificado y callbacks OIDC/documentales exactos. Los navegadores pueden necesitar reinstalar la PWA y autorizar de nuevo sus notificaciones; no transferir sesiones ni suscripciones a otros usuarios.

Hacer una copia consistente de SQLite: detener ordenadamente el servicio sólo después de comprobar que no hay operaciones comerciales en ejecución ni inciertas pendientes de revisión, o usar una herramienta de backup SQLite; no copiar sólo el archivo principal durante escrituras/WAL. Restaurar con el servicio detenido, preservar los archivos privados y verificar permisos antes de abrir LAN. No borrar recibos inciertos para reintentar: verificar primero en Protheus. Los trabajos consultivos recuperan préstamos vencidos y vuelven a comprobar usuario, permisos y fuentes; las propuestas nunca se ejecutan por reinicio.

Después de restaurar: comprobar `/health` (proceso), disponibilidad en Conexiones, ingreso y roles, tarjetas pendientes de verificación, última revisión, resumen diario y notificaciones optativas. Revalidar documentos y consentimientos corporativos con cuentas de prueba. No declarar entregados/facturados los casos por errores o ausencia de conexión. La homologación SQL, bloqueos, personalizaciones, volumen y transacciones de esta instalación se valida por separado; una prueba local no los sustituye.
